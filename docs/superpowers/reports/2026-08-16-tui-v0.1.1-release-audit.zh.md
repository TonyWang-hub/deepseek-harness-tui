# TUI v0.1.1 发布就绪审计

[English](2026-08-16-tui-v0.1.1-release-audit.md) | 中文

## 结论

仓库尚未具备创建 `v0.1.1` 产品 tag 的条件。候选提交必须使用 Node 24 Action 运行时通过 TUI CI 矩阵，并且项目必须决定产品 `v*` tag 是否有意与包 manifest 携带的 dsh npm family 版本保持独立。

发布候选必须指向本报告之后最终通过验证的提交。它至少必须包含确定性 CI 测试修复（`05d46803a6`）、TTY 渲染修复（`1b5ef1a385`、`1c733681ef`）、Node 24 Action 升级（`345bc2eacb`）以及当前状态文档（`2e16158ac2`）。创建或移动 tag 以及发布 GitHub release 都需要人工发布权限。

## 产品发布流程

唯一的产品 tag 是 `v0.1.0`，指向 `eeb1144230`，不包含上述修复。GitHub 产品 release 使用 `v*` tag，但仓库发布脚本不会根据包版本验证该约定。因此，发布 `v0.1.1` 必须明确决定其源码 release 版本可以不同于 `0.1.0-rc.5` 包 manifest，或者另行执行经过授权的 npm family 版本升级。

## npm 发布流程

dsh npm family 包含 224 个成员，共享 `0.1.0-rc.5` 版本。其脚本要求 `dsh-v*` tag，而不是产品 `v*` tag；当前不存在 `dsh-v*` tag。本 fork 的手动 release workflow 没有 `publish` 输入，因此 publish job 仍被禁用。npm 发布需要经过授权的 family 全量版本升级、lockfile 重新生成、合并后创建匹配的 `dsh-v*` tag，以及明确具备发布能力的 workflow；这些操作都不属于本次收尾。

## 已验证证据

- `pnpm run release:verify --family dsh` 对 224 个 `0.1.0-rc.5` 成员验证通过。
- `pnpm exec vitest run scripts/release/families.spec.ts` 的 17 项测试全部通过。
- `actions/checkout@v6`、`pnpm/action-setup@v6` 与 `actions/setup-node@v6` 均声明 Node 24 Action 运行时。
- TUI workflow diff 只修改这三个 Action 主版本，并保留受测的 Node 22 产品 lane。
- 未修改任何 tag、包版本、lockfile 或发布设置。

## 剩余授权操作

1. 在最终候选提交上完成本地文档、lint、发布及 diff 检查。
2. 推送候选提交，并要求其在 Ubuntu 与 macOS 上通过 TUI CI，且不再出现 Node 20 Action 运行时警告。
3. 决定并记录产品 `v*` 版本是否独立于 npm family 版本。
4. 完成决策且 CI 通过后，由具备权限的人员创建合适的 tag 与 GitHub release。不要移动 `v0.1.0`。
