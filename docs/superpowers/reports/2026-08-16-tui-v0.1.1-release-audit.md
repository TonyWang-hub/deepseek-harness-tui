# TUI v0.1.1 release readiness audit

English | [中文](2026-08-16-tui-v0.1.1-release-audit.zh.md)

## Verdict

The repository is not ready to create a `v0.1.1` product tag. The candidate must pass the TUI CI matrix with the Node 24 Action runtimes, and the project must decide whether product `v*` tags intentionally remain independent from the dsh npm-family version carried by package manifests.

A release candidate must point to the final verified commit after this report. At minimum, it must contain the deterministic CI-test fixes (`05d46803a6`), TTY rendering fixes (`1b5ef1a385`, `1c733681ef`), Node 24 Action upgrade (`345bc2eacb`), and current-state documentation (`2e16158ac2`). Creating or moving a tag and publishing a GitHub release require human release authority.

## Product release track

The only product tag is `v0.1.0`, which points to `eeb1144230` and excludes the fixes listed above. GitHub product releases use `v*` tags, but no repository release script validates that convention against package versions. A `v0.1.1` release therefore requires an explicit decision that its source-release version may differ from the `0.1.0-rc.5` package manifests, or a separate authorized npm-family version bump.

## npm release track

The dsh npm family contains 224 members at one shared `0.1.0-rc.5` version. Its scripts require `dsh-v*` tags, not product `v*` tags, and no `dsh-v*` tag exists. This fork's manual release workflow has no `publish` input, so its publish job remains disabled. An npm release requires an authorized family-wide version bump, lockfile regeneration, a matching `dsh-v*` tag after merge, and an explicitly publication-capable workflow; none of those operations belongs to this closeout.

## Verified evidence

- `pnpm run release:verify --family dsh` passes for 224 members at `0.1.0-rc.5`.
- `pnpm exec vitest run scripts/release/families.spec.ts` passes all 17 tests.
- `actions/checkout@v6`, `pnpm/action-setup@v6`, and `actions/setup-node@v6` declare the Node 24 Action runtime.
- The TUI workflow diff changes only those three Action majors and preserves the tested Node 22 product lane.
- No tag, package version, lockfile, or publication setting changed.

## Remaining authorized actions

1. Complete local documentation, lint, release, and diff checks on the final candidate.
2. Push the candidate commit and require a successful TUI CI run on both Ubuntu and macOS with no Node 20 Action-runtime warning.
3. Decide and document whether product `v*` versions are independent from npm-family versions.
4. After the decision and green CI, have an authorized human create the appropriate tag and GitHub release. Do not move `v0.1.0`.
